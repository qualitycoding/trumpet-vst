[High] plan/DECISIONS.md:452-456 (D-025 `rc-artifacts`), PLAN.md S-017 step 4, DECISIONS.md:513 (D-026 R-019 path a) — The job "fails unless `git rev-parse HEAD^` starts with" the sha named in `GATE-G-002.md`, and the marker is "pushed directly on top of" that commit. The gate protocol (GATES.md:3-11, D-025 "only after `GATE-G-002.RESPONSE.md` is committed") forces at least two commits between the approved code commit and the marker: the commit with `GATE-G-002.md` (which names the sha, so it comes after it) and the response commit. A commit cannot name its own sha, so HEAD^ is the response commit and never the named sha. The first approved run fails, and the owner's path (a) fails the same way. S-017's "Done when" (green `rc-artifacts` run on the marker) cannot be met without a deviation or a second gate cycle. Also "builds the marker commit (identical tree)" is false, because the gate files differ from the approved commit. — Fix: use the round-4 R-034 mitigation instead of HEAD^. The job (fetch-depth: 0) requires `git merge-base --is-ancestor <sha7> HEAD` and `git diff --quiet <sha7> HEAD -- . ':(exclude)GATE-*.md'`. Replace "directly on top of it ... marker's parent" and "identical tree" with "an ancestor; only `GATE-*.md` differ". Alternatively define sha7 as the response commit's parent, and write that in S-017 step 4 and D-026 R-019.

Related gaps: D-010 still says legato "if and only if another note is held" and "no note held (even if still ringing) -> re-articulated" with no pedal exception. Nothing says what legato means while the D-007 40 ms release is already running. A same-pitch note-on under CC68 is undefined (tie or re-attack). Whether CC121 clears the pedal is not stated (CC121 lists only breath, bend, vibrato, overblow). No frozen test covers CC68, and no step or "Done when" mentions it. — Fix: in D-014 name the additive member `void TrumpetVoice::setLegatoPedal(bool) noexcept` (implemented in S-011, log in DEVIATIONS.md, like `releaseOverblowControl`), and have the processor call it for CC68. State that the voice measures the 20 ms in rendered samples from the last note-off. Add "except with the legato pedal (D-014)" to D-010. Define the legato-from-release behaviour (cancel the release, slur from the current lip/bore state), the same-pitch case, and that CC121 and prepare clear the pedal. Add S-011 and S-013 action lines and a Done-when check, for example a DEVIATIONS.md entry plus a non-frozen smoke test, or an explicit "untested, G-006 item 8".

4. [Low] plan/DECISIONS.md:277-278 (D-014 CC11 restore) — The restore is underspecified in three ways. (i) Is it an instant jump to 1 or a smoothed return? A smoothed return attenuates the first 10 ms of a note after a CC11 = 0 tail. (ii) Is it applied before or after the MIDI events of the block in which the play-head starts? Applied after, it discards a host-chased CC11 sent at sample 0. (iii) What is the initial "previous play state" at construction and prepareToPlay, and what happens in Standalone with no play-head? The register (R-033) mentions a reset in `prepareToPlay`, but D-014 does not. — Fix: add "set the gain and its smoother state to 1 at the start of the block, before that block's events; the previous play state is false after construction/prepareToPlay; no play-head means no reset".
